# Generated interceptors

This page shows the code the generator writes for each `Verify`, `Throws` and `ThrowsAsync` call. After reading it you can find the method that runs in place of a call, and see where its message comes from.

## One interceptor per call

The generator writes one file per source file that has calls. The file holds one method per call. Each method carries `[InterceptsLocation]`, so the compiler calls it in place of the `VerifySyntax` method at that location. The method takes the same parameters as the method it replaces.

The method checks the condition and, when it fails, passes the message for the shape, the file and the line to `VerifyFailure`. All three are string and number literals, so nothing is looked up at run time. A `Throws` or `ThrowsAsync` interceptor is generic in the exception type and passes it through.

The method name is the kind of call and its line and column in the source file, such as `Verify_15_9`. A stack trace through a failed check shows that name.

## Example

```cs
[Fact]
public async Task Checkout_reports_an_empty_cart()
{
    var order = new Order(Id: 7, Total: 40);
    Verify(order.Total == 40);
    Verify(order.Id > 0, $"order {order.Id} has no id");

    var error = Throws<InvalidOperationException>(() => new Cart().Checkout());
    Verify(error.Message == "The cart is empty.");

    var exact = ThrowsExactly<InvalidOperationException>(() => new Cart().Checkout());
    Verify(exact.Message == "The cart is empty.");

    var timeout = await ThrowsAsync<TimeoutException>(() => new Client().GetAsync("/orders/7"));
    Verify(timeout.Message.Contains("/orders/7"));
}
```

## The file-local attribute

The compiler finds `InterceptsLocationAttribute` by its name, and the base class library does not declare it. Each generated file declares its own copy as a `file` class, so the copies in different files do not conflict.

## Interceptors namespace

The compiler accepts interceptors only from namespaces listed in the `InterceptorsNamespaces` property. The generated methods are in `VerificationGlue.Generated`, and `buildTransitive/VerificationGlue.props` in the package adds that namespace. Without it the build fails with CS9137.
