# VGT0008: A test with [Mock] parameters uses a shared container that cannot take overrides

## What it means

The test has `[Mock]` parameters, and its container is shared with `Scope = ContainerScope.Class` or `Scope = ContainerScope.Assembly`. Each test gets a child of the shared container. The bootstrap does not implement `ISupportsChildOverrides`, so its children do not apply the test's overrides. The system under test would get the shared container's service and not the test's mock.

A bootstrap built on `Microsoft.Extensions.DependencyInjection` whose children are scopes has this limit, because `CreateScope()` adds no registrations.

The runner makes the same check before it runs each test, because a scope listener can add overrides that the build cannot see. That test fails with a message that starts with `VGT0008:` and does not run.

## Example that triggers it

```csharp
[Container<ShopBootstrap>(Scope = ContainerScope.Class)]
public partial class OrderServiceTests
{
    [VerifyTest]
    public void Create_stamps_the_order_with_the_clock([Mock] IClock clock, OrderService sut) { }
}
```

The build reports:

```text
error VGT0008: The test 'Create_stamps_the_order_with_the_clock' has [Mock] parameters, but its container TestsContainers.ShopBootstrap is shared with Scope = Class and TestsContainers.ShopBootstrap does not implement ISupportsChildOverrides, so the system under test would not receive the mocks
```

## The fix

Do one of these:

- Remove `Scope`, so each test builds its own container with its mocks.
- Use a bootstrap that implements `ISupportsChildOverrides` and applies `context.Overrides` in `CreateChildAsync`. [Containers and scopes](../guide/containers-and-scopes.md#overrides-under-a-shared-container) shows one.
- Put the test that needs mocks in a class with a test-scoped container, and keep the shared container for tests without mocks.

## When to suppress it

Do not suppress it. The mock would not reach the system under test, so the test would check the wrong service.
