# VG0006: A part of a Verify condition cannot be captured

## What it means

Tier 3 rewrites the condition so that each part is stored in a local as it runs. Some parts cannot be stored without changing what the code does, so the failure message shows their text with `<unavailable>` in place of the value:

- A value whose type is a `ref struct`, such as `Span<int>`, or a pointer. It cannot be stored in the local that the failure path reads.
- The receiver of a call when the receiver is a mutable struct. A copy in a local would take the change that the call makes, and the original would not.

The other parts of the condition are still captured. The analyzer reports only in a method that tier 3 rewrites. [`RewriteAnalyzerSpecs.cs`](../../test/VerificationGlue.Generator.Specs/RewriteAnalyzerSpecs.cs) holds the cases that CI runs.

## Example that triggers it

```csharp
[Verify]
public static void IsEmpty(int[] values) => Verify(values.AsSpan().Length == 0);
```

The build reports:

```text
info VG0006: 'values.AsSpan()' is not captured, because its type is a ref struct. The failure message shows its text with the value unavailable.
```

The failure message shows the length and the array, and marks the span:

```text
Verify failed: values.AsSpan().Length == 0
  values.AsSpan().Length → 2
  values.AsSpan()        → <unavailable>
  values                 → 2 items: 1, 2
```

## The fix

Store the value in a variable of a type that can be captured, and verify that:

```csharp
var length = values.Length;
Verify(length == 0);
```

## When to suppress it

Suppress it when the unavailable value does not help explain a failure. The diagnostic is information only.
