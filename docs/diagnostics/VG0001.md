# VG0001: Because or WithMessage outside a method that tier 3 rewrites

## What it means

`.Because(...)` or `.WithMessage(...)` follows a `Verify` call that tier 3 does not rewrite. In tiers 1 and 2, `Verify` throws as soon as the condition is false, so the chained call never runs and its text never reaches the failure message.

Tier 3 rewrites a `Verify` statement when all of these hold:

- The project sets the `VerificationGlueRewrite` property to `true`.
- The method has `[Verify]` or an attribute marked `[VerifyRewrite]`, and is eligible. The [tiers guide](../guide/tiers.md) lists the rules.
- The call is a statement of its own, such as `Verify(x == 1).Because("...");`. It is not inside a lambda or a local function.

The error is reported on the name of the chained call. [`RewriteAnalyzerSpecs.cs`](../../test/VerificationGlue.Generator.Specs/RewriteAnalyzerSpecs.cs) holds the cases that CI runs.

## Example that triggers it

With `VerificationGlueRewrite` not set:

```csharp
[Verify]
public static void Discount(Order order) => Verify(order.Total == 36).Because("the discount applies");
```

The build reports:

```text
error VG0001: '.Because' adds text only in a method that tier 3 rewrites. Here Verify throws before '.Because' runs, so the text never reaches the message.
```

## The fix

Turn tier 3 on in the project file, and keep the call in an eligible `[Verify]` method:

```xml
<PropertyGroup>
  <VerificationGlueRewrite>true</VerificationGlueRewrite>
</PropertyGroup>
```

Or use the interpolated message, which works in every tier:

```csharp
Verify(order.Total == 36, $"the discount applies to order {order.Id}");
```

## When to suppress it

Do not suppress it. The text it reports would be lost.
