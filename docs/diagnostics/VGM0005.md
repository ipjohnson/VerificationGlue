# VGM0005: Setup is not on a mock call

## What it means

`Returns` and `Throws` do not look at the value they are called on. They apply to the last mock call made in the same async flow. In `calc.Add(1, 2).Returns(3)`, that call is `calc.Add(1, 2)`.

When the receiver is not a call to a mock member, such as a property of a string or a local variable, the setup applies to whichever mock call came before it. NSubstitute cannot catch this at run time, so it rebinds the earlier call without an error. VGM0005 reports it at build time.

## Example that triggers it

```csharp
calc.Add(1, 2);
"abc".Length.Returns(3);
```

```text
error VGM0005: '"abc".Length' is not a call to a mock member, so Returns would apply to whichever mock call came before it
```

Without the error, `calc.Add(1, 2)` would return 3.

A local variable also reports it, because the call that produced the value may not be the last one:

```csharp
var sum = calc.Add(1, 2);
sum.Returns(3);
```

## The fix

Call `Returns` or `Throws` directly on the mock call:

```csharp
calc.Add(1, 2).Returns(3);
```

## When to suppress it

Suppress it only when the setup is meant to bind the last mock call of the flow, such as a test of the setup rule itself. Use `#pragma warning disable VGM0005` around that code.
