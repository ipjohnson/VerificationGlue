# VGT0002: A [Row] does not match the test method's parameters

## What it means

A `[Row]` on a `[VerifyTest]` method has values the test method cannot take. The build fails, and the row is not registered. The message gives the reason:

- A value does not convert to its parameter type without a cast, such as a `string` for an `int` parameter or a `double` for an `int` parameter.
- An `int` value is out of range for a smaller integer parameter, such as `300` for a `byte`.
- The value is `null` and the parameter is a value type that is not nullable.
- The row has more values than the method has parameters, or no values at all.
- The value is a type that the generated registration cannot reach, such as `typeof` of a private class.

## Example that triggers it

```csharp
[VerifyTest]
[Row("two", 10, 20)]
public void Totals(int qty, int price, int expected) { }
```

The build reports:

```text
error VGT0002: The [Row] on 'Totals' gives "two" (string) for the parameter 'qty' of type int, so the row is not registered
```

## The fix

Give each value in the parameter's type, in the parameter's order. Write `[Row(2, 10, 20)]` in the example above. Attribute arguments cannot be `decimal`. A whole number fits a `decimal` parameter, and a fraction can be passed as a `string` and parsed in the test. [Data rows](../guide/data-rows.md#value-types) lists the conversions a row accepts.

## When to suppress it

Do not suppress it. The row would not be registered, so its case would never run.
