# VGT0003: [RunAfter] makes schedule groups wait on each other

## What it means

`[RunAfter("name")]` on a test class makes the schedule group of its tests wait until every test of the named group has finished. When the groups that `[RunAfter]` names lead back to the group that waits, none of those groups can start. The build reports each `[RunAfter]` in the loop, with the path of groups that closes it.

A class whose tests are in group `a` and that carries `[RunAfter("a")]` waits on its own group, which is the shortest loop.

The default scheduler checks again when the run starts, in case the diagnostic is suppressed. It then runs none of the selected tests, and each one fails with a message that names VGT0003 and the groups.

## Example that triggers it

```csharp
[ScheduleGroup("database")]
[RunAfter("reports")]
public partial class OrderRepositoryTests { /* ... */ }

[ScheduleGroup("reports")]
[RunAfter("database")]
public partial class DailyReportTests { /* ... */ }
```

The build reports:

```text
error VGT0003: [RunAfter("reports")] makes the schedule group 'database' wait on itself through database -> reports -> database, so none of these groups can start
error VGT0003: [RunAfter("database")] makes the schedule group 'reports' wait on itself through reports -> database -> reports, so none of these groups can start
```

## The fix

Decide which group has to finish first, and remove the `[RunAfter]` that points the other way. In the example, `DailyReportTests` reads what the database tests wrote, so `OrderRepositoryTests` keeps no `[RunAfter]`.

When two classes only must not run at the same time, and neither has to go first, give their tests the same `[Resource]` key instead. [Scheduling groups and resources](../guide/scheduling-groups-and-resources.md#keep-tests-apart-with-a-resource) shows how.

## When to suppress it

Do not suppress it. The groups in the loop cannot start, so the run fails each of their tests.
