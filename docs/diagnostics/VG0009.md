# VG0009: Write the condition as a lambda to list each part's value

## What it means

A test calls `Verify(condition)` or `Check(condition)` where `Verify(() => condition)` or `Check(() => condition)` would work as well. With the lambda, a failure lists the value of each part of the condition, in any test framework. `Verify(bool)` gives only the source text and the shape of the condition.

VG0009 is a suggestion by default. It reports only in a method that has one of these attributes, matched by the attribute's name without the `Attribute` suffix, in any namespace:

- `Fact` or `Theory`, as in xunit;
- a name that starts with `Test` or ends with `Test` or `TestMethod`, such as `Test`, `TestCase`, `TestMethod`, `DataTestMethod` and `VerifyTest`, and custom attributes such as `MyTest`;
- `Verify`, so that you can opt in any other method.

A call in a helper method without such an attribute is not reported.

VG0009 does not report a call where the lambda would not compile or would lose something:

- the condition contains `await`, which a `Func<bool>` cannot hold;
- the condition reads a `Span<T>` or another `ref struct` local or parameter, a `ref`, `in` or `out` local or parameter, or `this` in a struct, which a lambda cannot capture;
- the condition declares an `out var` that later code reads, or assigns a variable through `out`;
- the condition reads a value that may be null and later code names it again, so it may rely on `Verify(bool)` making the value not null through `[DoesNotReturnIf(false)]`;
- the call has an interpolated message or an explicit `expression` argument, because no lambda overload takes them;
- the call's result is used, as in `.Because(...)` or an expression-bodied member that returns it;
- the condition is a constant or assigns a value, which VG0002 and VG0003 report.

It also does not report in a method that tier 3 rewrites, which already lists each part's value. [`LambdaAnalyzerSpecs.cs`](../../test/VerificationGlue.Generator.Specs/LambdaAnalyzerSpecs.cs) holds the cases that CI runs.

## Example that triggers it

```csharp
[Fact]
public void Total_is_forty()
{
    var order = new Order(Id: 7, Total: 40);
    Verify(order.Total == 40);
}
```

The IDE shows:

```text
info VG0009: Write 'Verify(() => order.Total == 40)' so that a failure lists the value of each part
```

## The fix

Write the condition as a lambda. The code fix makes this change:

```csharp
Verify(() => order.Total == 40);
```

Keep `Verify(bool)` when the condition awaits, reads a `Span<T>` or another `ref struct`, or checks a value for null that the next lines use without a null check. VG0009 does not report those calls.

### Set the severity

Set `VerificationGlueLambdaSeverity` in the project to `none`, `info`, `warning` or `error`. The default is `info`.

```xml
<PropertyGroup>
  <VerificationGlueLambdaSeverity>warning</VerificationGlueLambdaSeverity>
</PropertyGroup>
```

With `warning` and `TreatWarningsAsErrors`, the build fails on VG0009. With `none`, VG0009 reports nothing. A `dotnet_diagnostic.VG0009.severity` entry in `.editorconfig` takes precedence over the property.

## When to suppress it

Suppress it in a test that checks the message `Verify(bool)` gives, or set `VerificationGlueLambdaSeverity` to `none` for a project that keeps `Verify(bool)` throughout.
