# VGM0002: Arg matcher is not an argument of a mock call

## What it means

`Arg.Any<T>()` and `Arg.Is<T>(...)` do not match anything on their own. Each call queues a matcher in the current async flow, and the next mock call in that flow takes it.

When the matcher is written directly as an argument of a mock member, the generator reads which parameter it belongs to and passes that position along. Anywhere else, the position is unknown. The matcher then goes to the first argument that holds the default value of its type, which can be the wrong argument. A matcher that no mock call takes stays queued and goes to the next mock call in the flow.

VGM0002 is a warning for a matcher that is stored in a local, passed to a method that is not a member of a mocked interface, or left unused.

VGM0002 is an error for an `Arg.Any<T>()` or `Arg.Is<T>(...)` passed to a member of the typed `Setup()` or `Calls()` surface. Each parameter there is an `Arg<T>`, and the matcher's return value converts to an exact match on the default value, such as `0`. The matcher itself stays queued for the next mock call.

## Example that triggers it

```csharp
var any = Arg.Any<int>();
calc.Add(0, any).Returns(3);
```

```text
warning VGM0002: 'Arg.Any<int>()' is not passed directly as an argument of a mock member, so its argument position is unknown and it waits for the next mock call
```

At run time the matcher goes to the first argument, because it holds `0`. The setup then matches `Add(any, 0)` instead of `Add(0, any)`.

```csharp
calc.Setup().Add(1, Arg.Any<int>()).Returns(3);
```

```text
error VGM0002: 'Arg.Any<int>()' is an NSubstitute-style matcher, so this Arg<T> parameter matches only the default value and the matcher waits for the next mock call. Use 'Arg<int>.Any()'.
```

## The fix

Write the matcher as the argument itself:

```csharp
calc.Add(0, Arg.Any<int>()).Returns(3);
```

In the typed surface, use the matchers on `Arg<T>`, which queue nothing:

```csharp
calc.Setup().Add(1, Arg<int>.Any()).Returns(3);
Verify(calc.Calls().Add(Arg<int>.Is(a => a > 0), 2) == 1);
```

## When to suppress it

Suppress the warning only in a test that checks what happens to a misplaced matcher. Any other use can bind to the wrong argument. Do not suppress the error. The typed member never matches what the matcher describes.
