# VGM0001: Type cannot be mocked

## What it means

The mock generator cannot write a class that implements the type, so it generates no mock for it. The message names the reason:

| Reason in the message | Cause |
|---|---|
| `'Create' is a static abstract member` | The interface or one of its base interfaces has a static abstract member. A class cannot implement it in a way a test could set up. |
| `'Hidden' is not accessible from this assembly, so it cannot be implemented` | The interface has an abstract member, such as an `internal` one, that the test project cannot see. |
| `it has members with pointer types, which need AllowUnsafeBlocks in the project` | A member uses a pointer type, and the project does not allow unsafe code. |
| `it is a struct`, `it is a sealed or static class` | Only interfaces can be mocked. |
| `class mocks are not supported yet` | Class mocks arrive in Phase 3 of `docs/design/mocks.md`. |
| `it is not accessible from this assembly` | The type is private, protected, or internal to another assembly that grants no `InternalsVisibleTo`. |
| `'Ledger<Payment>.Line' is nested in a generic type whose type arguments come from an extern-aliased assembly, and the generator cannot write its name` | The type, or a type in one of its members, is nested in a generic type, and a type argument comes from an assembly the project references through an `extern alias`. The generator would write that argument with `global::`, which does not compile. Use a type argument from an assembly referenced without an alias, or mock an interface that does not name the nested type. |
| `it is an open generic type` | `[assembly: GenerateMock(typeof(IRepository<>))]` names a generic type without type arguments. Only a closed type, such as `typeof(IRepository<Order>)`, can be registered. |

The error points at the place that names the type: the `Mock.Of<T>()` call, the `[Mock]` attribute or the `[assembly: GenerateMock]` attribute.

Every reason has a case in [the shape files](../../test/VerificationGlue.Mocks.Generator.Specs/Shapes), which CI compiles.

## Example that triggers it

An interface with a static abstract member, from [StaticAbstract.cs](../../test/VerificationGlue.Mocks.Generator.Specs/Shapes/StaticAbstract.cs):

```csharp
public interface IFactory<TSelf> where TSelf : IFactory<TSelf>
{
    static abstract TSelf Create();
    int Value { get; }
}
```

A mock of `IFactory<TSelf>` reports:

```text
error VGM0001: 'Shapes.StaticAbstract.IFactory<TSelf>' cannot be mocked: 'Create' is a static abstract member
```

## The fix

Mock a different type. For a static abstract interface, mock an interface that holds only its instance members, such as one that `IFactory<TSelf>` extends.

For a pointer member, set `AllowUnsafeBlocks` in the test project:

```xml
<PropertyGroup>
  <AllowUnsafeBlocks>true</AllowUnsafeBlocks>
</PropertyGroup>
```

The mock then compiles, and each pointer member reports VGM0003.

For an inaccessible type or member, add `InternalsVisibleTo` for the test project to the assembly that declares it.

## When to suppress it

Do not suppress it. No mock is generated, so a test that asks for one fails.
