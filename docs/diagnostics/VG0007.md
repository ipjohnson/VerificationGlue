# VG0007: Check where no VerifyScope can report it

## What it means

`Check` records a failure in the current `VerifyScope`, and the scope reports every failure when it ends. The call is in a member that runs where no scope can be open:

- a static constructor,
- a finalizer,
- a method marked `[ModuleInitializer]`.

With no open scope, `Check` throws at once, as `Verify` does. The code reads as if it continues after a failure, and it does not. A `CheckEquivalent` call there gets the same warning, and the fix is `VerifyEquivalent`. [`RewriteAnalyzerSpecs.cs`](../../test/VerificationGlue.Generator.Specs/RewriteAnalyzerSpecs.cs) holds the cases that CI runs.

## Example that triggers it

```csharp
public class Settings
{
    static Settings()
    {
        Check(Environment.ProcessorCount > 0);
    }
}
```

The build reports:

```text
warning VG0007: Check in the static constructor of 'Settings' runs where no VerifyScope can be open, so a failure throws at once. Use Verify instead.
```

## The fix

Use `Verify`, which says that the code stops on a failure:

```csharp
static Settings()
{
    Verify(Environment.ProcessorCount > 0);
}
```

## When to suppress it

Suppress it when the member opens its own scope with `VerifyScope.Begin()` around the `Check` calls.
