# VGT0006: An attribute is not passed to extension points

## What it means

The generator writes each attribute of a test, its class and its assembly as a `new` expression, so extension points find them in `TestContext.Attributes` without reflection. Attributes from `System` namespaces are left out on purpose. This warning names an attribute that the generated file cannot write, so the test runs without it in `TestContext.Attributes`. The message names the reason:

| Reason in the message | Cause |
|---|---|
| `the generated registration cannot access OrderTests.SecretAttribute` | The attribute type is `private`, `protected` or `file`, or `internal` to another assembly. |
| `the generated registration cannot access its constructor` | The constructor the attribute uses is not accessible. |
| `an argument cannot be written as C#` | An argument names a type that is not accessible, has an error, or comes from an assembly the project references through an `extern alias`. For an attribute written from its syntax, an argument is also not a constant, an enum member, `nameof`, `typeof` or an array of them. |
| `its type cannot be resolved. Another source generator may produce it, and this generator cannot see that output` | Source generators cannot see each other's output, so an attribute class that another generator writes is unknown here. |

A named argument never causes this warning. C# accepts only a public field or a public read-write property as a named argument, and the registration can set any such member.

## Attributes that DependencyModules writes

The registration writes an unresolved attribute from its syntax when the project references `DependencyModules.Runtime` and a `ServiceCollectionAttribute` or `ServiceCollectionAttribute<T>` applies to the test from its method, its class or its assembly. This covers a module declared in the test project, whose attribute class the DependencyModules generator writes. For `[SutModule(2, Name = "x")]` or `[SutModuleAttribute(2, Name = "x")]`, the generator finds the module class `Shop.SutModule` at the usage and writes `new global::Shop.SutModuleAttribute(2) { Name = "x" }` in that type's namespace. The attribute is then in `TestContext.Attributes` and `TestContainerContext.Attributes`, and this warning is not reported for it.

The attributes of a class are written this way when the rule holds for any test of the class, and the attributes of the assembly when it holds for any test of the assembly. With no type of that name at the usage, the warning keeps the reason `its type cannot be resolved`. An argument that the generator cannot read reports `an argument cannot be written as C#`.

## Example that triggers it

```csharp
public partial class OrderTests
{
    private sealed class SecretAttribute : Attribute { }

    [VerifyTest]
    [Secret]
    public void M() { }
}
```

The build reports:

```text
warning VGT0006: The attribute 'OrderTests.SecretAttribute' is not passed to extension points, because the generated registration cannot access OrderTests.SecretAttribute
```

## The fix

Make the attribute class, its constructor and the types its arguments name `internal` or `public`. Declare an attribute that another generator writes in a referenced project instead, where this generator can see it. For a DependencyModules module, add `[ServiceCollection]` to the test, its class or its assembly.

## When to suppress it

Suppress it when no extension point reads the attribute, such as an attribute that only an analyzer reads.
