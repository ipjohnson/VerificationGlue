# VG0010: A VerifyEquivalent option does not name a member the comparer reads

## What it means

The generator reads the options of `VerifyEquivalent(actual, expected, options => ...)` from the source of the call and writes them into the comparer. The lambda never runs. So each option must name a member in a form the generator can read: a chain of member accesses on the lambda's parameter, such as `x => x.Customer.Address`. `!` and `?.` may appear in the chain.

The option is left out of the comparer, and the build reports this error, in these cases:

- The lambda is not a chain of member accesses. It calls a method, reads an index, or computes a value.
- A member on the path compares with `Equals`, such as a string, so the comparer does not read the member after it.
- The member is not a public instance field or property, which are the only members the comparer reads.
- `Unordered` names a member that is not an array or a list that the comparer walks.
- `Ignore` names the value itself, as `x => x`.
- The options argument is not a lambda that calls `Unordered` and `Ignore` on its parameter, such as a variable that holds the lambda.

[`EquivalenceSpecs.cs`](../../test/VerificationGlue.Generator.Specs/EquivalenceSpecs.cs) holds the cases that CI runs.

## Example that triggers it

```csharp
public sealed record Customer(string Name, string Note);

public sealed record Order(int Id, Customer Customer, List<string> Tags);

VerifyEquivalent(parsed, expected, options => options.Ignore(x => x.Customer.Note.Trim()));
```

The build reports:

```text
error VG0010: The VerifyEquivalent option 'x => x.Customer.Note.Trim()' is not applied, because it is not a chain of member accesses on the lambda's parameter, such as 'x => x.Lines'
```

## The fix

Name the member itself:

```csharp
VerifyEquivalent(parsed, expected, options => options.Ignore(x => x.Customer.Note));
```

An option cannot name a member of the items of an array or a list, such as `x => x.Lines[0].Note`. To compare a list without one member of its items, project both lists to the members you want before the call.

## When to suppress it

Do not suppress it. The comparer compares the member that the option names, so the test checks something other than what the call says.
