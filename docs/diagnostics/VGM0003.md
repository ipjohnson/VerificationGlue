# VGM0003: Member cannot be mocked

## What it means

The mock implements the member, but calling it throws `NotSupportedException`. The rest of the mock works.

A mock records each call's arguments in an `object?[]` and returns values through it. A value that cannot be boxed cannot travel that way. The member reports VGM0003 when it has any of these:

- A parameter or return value that is a `ref struct`, such as `Span<T>` or `ReadOnlySpan<char>`.
- A parameter or return value whose type is a method type parameter with `allows ref struct`.
- A parameter, return value or property of a pointer or function pointer type.

[RefStruct.cs](../../test/VerificationGlue.Mocks.Generator.Specs/Shapes/RefStruct.cs) and [Pointers.cs](../../test/VerificationGlue.Mocks.Generator.Specs/Shapes/Pointers.cs) hold the cases that CI compiles.

## Example that triggers it

```csharp
public interface ISpans
{
    int Parse(ReadOnlySpan<char> text);
}
```

A mock of `ISpans` reports:

```text
warning VGM0003: 'Shapes.RefStruct.ISpans.Parse' cannot be mocked: parameter 'text' is the ref struct 'System.ReadOnlySpan<char>'. The generated member throws NotSupportedException.
```

## The fix

Keep the code under test away from the member, or wrap the interface in one whose members take arrays, strings or `Memory<T>`.

Whether `ref struct` parameters get their own path is an open question in `docs/design/mocks.md`.

## When to suppress it

Suppress it when the test never calls the member. The rest of the mock works.
