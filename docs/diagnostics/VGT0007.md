# VGT0007: VerificationGlue version does not match VerificationGlue.Tests

## What it means

The project references a version of `VerificationGlue` that differs from the version of `VerificationGlue.Tests`. `VerificationGlue.Tests` is built against one exact version of `VerificationGlue`, and its generator reports this error when the two differ. Build metadata after `+` is ignored.

## Example that triggers it

A project that pins `VerificationGlue` to a different version than `VerificationGlue.Tests`:

```xml
<ItemGroup>
  <PackageReference Include="VerificationGlue.Tests" Version="0.1.0" />
  <PackageReference Include="VerificationGlue" Version="0.2.0" />
</ItemGroup>
```

The build fails with:

```text
error VGT0007: The project references VerificationGlue 0.2.0, but VerificationGlue.Tests 0.1.0 requires VerificationGlue 0.1.0. Reference the same version of both packages.
```

## The fix

Reference only `VerificationGlue.Tests`. It depends on the exact `VerificationGlue` and `VerificationGlue.Mocks` versions it was built with, so NuGet restores the matching ones.

<!-- snippet: reference-verificationglue-tests -->
<a id='snippet-reference-verificationglue-tests'></a>
```csproj
<ItemGroup>
  <PackageReference Include="VerificationGlue.Tests" Version="$(VerificationGlueVersion)" />
</ItemGroup>
```

<!-- endSnippet -->

The sample sets `VerificationGlueVersion` to the version it tests. A project writes the version number there.

If the project must reference `VerificationGlue` directly, give it the same version as `VerificationGlue.Tests`.

## When to suppress it

Do not suppress it. The packages are built and tested only as a matched set, so a mismatched pair is not supported.
