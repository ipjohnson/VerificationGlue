# VGM0004: Mock.Of<T>() reaches a type with no generated mock

## What it means

The generator makes a mock for each type named at a `Mock.Of<T>()` call, in a `[Mock]` attribute or in `[assembly: GenerateMock(typeof(T))]`. Inside a generic helper, `Mock.Of<T>()` names only the type parameter `T`, so the generator cannot tell which mock to make.

VGM0004 follows each call to the helper in the project. When a call passes a type that nothing else names, `Mock.Of<T>()` throws `InvalidOperationException` at run time, and the warning reports it at the `Mock.Of<T>()` call. The call to the helper is the diagnostic's additional location.

The check sees calls in the same project, one level deep. A helper called with a type parameter of another helper, or from another project, is not checked.

## Example that triggers it

```csharp
public class Tests
{
    public void Run()
    {
        var clock = Make<IClock>();
    }

    private static T Make<T>() where T : class => Mock.Of<T>();
}
```

```text
warning VGM0004: 'Tests.Make<T>()' calls Mock.Of<T>() with T = 'IClock', but no mock of 'IClock' is generated. Add [assembly: GenerateMock(typeof(IClock))].
```

## The fix

Name the type for the generator, once in the project:

```csharp
[assembly: GenerateMock(typeof(IClock))]
```

A `Mock.Of<IClock>()` call or a `[Mock] IClock` parameter anywhere in the project also works.

## When to suppress it

Suppress it when another project registers the mock before the helper runs, such as a shared test library that names the type itself.
