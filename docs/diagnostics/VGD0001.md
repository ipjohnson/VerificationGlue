# VGD0001: The type in [ServiceCollection<T>] has no Configure method the generator can call

## What it means

`[ServiceCollection<T>]` adds the services that `T` registers to the container of the tests. The generator in `VerificationGlue.Tests.DependencyInjection` writes a call to a static `Configure` method on `T`, so the container calls it with no reflection. It accepts one of these two methods:

```csharp
public static void Configure(IServiceCollection services)
public static void Configure(IServiceCollection services, TestContainerContext context)
```

The method can be declared on `T` or on a base type of `T`. When `T` has neither method, the generator cannot write the call, so it reports an error. The message names `T` and lists each `Configure` method that `T` has.

## Example that triggers it

```csharp
[ServiceCollection<string>]
public partial class OrderTests
{
    [VerifyTest]
    public void Creates_an_order(OrderService sut)
    {
        // ...
    }
}
```

The build reports:

```text
error VGD0001: [ServiceCollection<string>] names 'string', but it has no method named Configure. The generator accepts a type with 'public static void Configure(IServiceCollection services)' or 'public static void Configure(IServiceCollection services, TestContainerContext context)'.
```

A `Configure` method with another shape is reported with its signature, such as an instance method:

```text
error VGD0001: [ServiceCollection<ShopServices>] names 'ShopServices', but its method 'public void Configure(IServiceCollection services)' does not have one of these signatures. ...
```

## The fix

Name a type with a public static `Configure` method that returns `void` and takes the service collection:

```csharp
public sealed class ShopServices
{
    public static void Configure(IServiceCollection services)
    {
        services.AddSingleton<IOrderStore, InMemoryOrderStore>();
        services.AddTransient<OrderService>();
    }
}

[ServiceCollection<ShopServices>]
public partial class OrderTests
```

Add a second parameter of `TestContainerContext` when the method needs the scope, its attributes or the test's output.

## When to suppress it

Do not suppress it. Without the generated call the container cannot add the services, and each test under the attribute fails when its container is built.
