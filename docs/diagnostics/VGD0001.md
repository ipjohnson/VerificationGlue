# VGD0001: The type in [ServiceCollection<T>] has no Configure method the generator can call and is not a DependencyModules module

## What it means

`[ServiceCollection<T>]` adds the services that `T` registers to the container of the tests. The generator in `VerificationGlue.Tests.DependencyInjection` writes a call to a static `Configure` method on `T`, so the container calls it with no reflection. It accepts one of these two methods:

```csharp
public static void Configure(IServiceCollection services)
public static void Configure(IServiceCollection services, TestContainerContext context)
```

The method can be declared on `T` or on a base type of `T`.

When the test project references DependencyModules, `T` can instead be a module. `T` counts as a module when it implements `IDependencyModule` or is a class marked `[DependencyModule]`. The generator writes `new T()`, so the module needs a public parameterless constructor.

When `T` is neither, the generator cannot add its services, so it reports an error. The message names `T` and lists each `Configure` method that `T` has. For a module, it says that `new T()` cannot create it.

## Example that triggers it

```csharp
[ServiceCollection<string>]
public partial class OrderTests
{
    [VerifyTest]
    public void Creates_an_order(OrderService sut)
    {
        // ...
    }
}
```

The build reports:

```text
error VGD0001: [ServiceCollection<string>] names 'string', but it has no method named Configure. The generator accepts a type with 'public static void Configure(IServiceCollection services)' or 'public static void Configure(IServiceCollection services, TestContainerContext context)', or a DependencyModules module with a public parameterless constructor.
```

A `Configure` method with another shape is reported with its signature, such as an instance method:

```text
error VGD0001: [ServiceCollection<ShopServices>] names 'ShopServices', but its method 'public void Configure(IServiceCollection services)' does not have one of these signatures. ...
```

A module whose constructor takes arguments is reported too, such as `[ServiceCollection<MailModule>]` for a `MailModule(string host, int port)`:

```text
error VGD0001: [ServiceCollection<MailModule>] names 'MailModule', but it is a DependencyModules module without a public parameterless constructor. ...
```

## The fix

Name a type with a public static `Configure` method that returns `void` and takes the service collection:

```csharp
public sealed class ShopServices
{
    public static void Configure(IServiceCollection services)
    {
        services.AddSingleton<IOrderStore, InMemoryOrderStore>();
        services.AddTransient<OrderService>();
    }
}

[ServiceCollection<ShopServices>]
public partial class OrderTests
```

Add a second parameter of `TestContainerContext` when the method needs the scope, its attributes or the test's output.

For a module with constructor arguments, put the module's own attribute on the test instead, and give it the arguments there, such as `[MailModule("smtp.example.com", 25)]`. Use `[ServiceCollection]` for the container.

## When to suppress it

Do not suppress it. Without the generated call the container cannot add the services, and each test under the attribute fails when its container is built.
