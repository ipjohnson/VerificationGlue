# VGA0003: A configuration attribute on a test method cannot reach a shared app

## What it means

`[AppSetting]`, `[AppEnvironment]`, `[Kestrel]` and `[WatchAppConfiguration]` set how the app of `[WebApp<TEntry>]` starts. With `Scope = ContainerScope.Class` or `ContainerScope.Assembly`, one app starts for the class or the assembly, before any test runs. An app of the class reads the attributes of the class and the assembly. An app of the assembly reads only the attributes of the assembly. An attribute on a test method would not reach either, so the generator reports it as an error.

## Example that triggers it

```csharp
[WebApp<ShopApiEntry>(Scope = ContainerScope.Class)]
public class OrderTests
{
    [VerifyTest]
    [AppSetting("Orders:MaxQuantity", "5")]
    public async Task Rejects_a_large_order(HttpClient client)
    {
        // ...
    }
}
```

The build reports:

```text
error VGA0003: The test 'Rejects_a_large_order' has [AppSetting], but its app [WebApp<Shop.Tests.ShopApiEntry>] is shared with Scope = Class and starts before the test, so it does not read the test's attributes. Move [AppSetting] to the class or the assembly, or give the app test scope.
```

The same holds for `[WebApp<TEntry>(Scope = ContainerScope.Assembly)]` on the assembly. The message then says `Scope = Assembly` and asks to move the attribute to the assembly.

## The fix

If every test of the class can run with the value, move the attribute to the class. Under assembly scope, move it to the assembly with `[assembly: AppSetting(...)]`.

```csharp
[WebApp<ShopApiEntry>(Scope = ContainerScope.Class)]
[AppSetting("Orders:MaxQuantity", "5")]
public class OrderTests
```

If only this test needs it, move the test to a class whose app has test scope, the default. That test then starts its own app with its own configuration:

```csharp
[WebApp<ShopApiEntry>]
public class OrderLimitTests
{
    [VerifyTest]
    [AppSetting("Orders:MaxQuantity", "5")]
    public async Task Rejects_a_large_order(HttpClient client)
    {
        // ...
    }
}
```

## When to suppress it

Do not suppress it. The app ignores the attribute, so the test runs against configuration it did not ask for.
