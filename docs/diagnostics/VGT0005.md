# VGT0005: A [RowSource] member is missing or returns the wrong shape

## What it means

A `[RowSource]` on a `[VerifyTest]` method names a member that cannot give the method's rows. The build fails, and the source's rows are not registered. The message gives the reason:

- The test class and its base classes have no method, property or field with that name.
- The member is not static.
- The member is private, so the generated registration cannot read it.
- The member is a method with parameters or type parameters.
- The member does not return `IEnumerable<T>` or `IAsyncEnumerable<T>`.
- A row has more values than the test method has parameters.
- A row value does not convert to its parameter type without a cast, such as a `string` for an `int` parameter.

## Example that triggers it

```csharp
public static IEnumerable<(string, int)> Orders() => [("two", 10)];

[VerifyTest]
[RowSource(nameof(Orders))]
public void Totals(int qty, int price) { }
```

The build reports:

```text
error VGT0005: The [RowSource] on 'Totals' names 'Orders', whose rows give string for the parameter 'qty' of type int, so its rows are not registered
```

## The fix

Make the member static, and public or internal. Return `IEnumerable<T>` or `IAsyncEnumerable<T>`, where `T` is a tuple of the method's first parameter types, in order, or the type of the first parameter. In the example above, return `IEnumerable<(int, int)>`. [Data rows](../guide/data-rows.md#rows-from-a-member) shows a member that works.

## When to suppress it

Do not suppress it. The source's rows would not be registered, so its cases would never run.
