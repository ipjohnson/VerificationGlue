# VG0003: Verify condition has a side effect

## What it means

The condition of a `Verify` call assigns a variable or field, or uses `++` or `--`. The check then changes the state it checks, and the test behaves differently when the check is removed or rewritten. The source text in the failure message also no longer matches the values the test goes on to use.

The analyzer looks at the condition itself. An assignment inside a lambda in the condition, such as `items.All(item => { sum += item; return true; })`, runs in the lambda and is not reported.

[`VerifyAnalyzerSpecs.cs`](../../test/VerificationGlue.Generator.Specs/VerifyAnalyzerSpecs.cs) holds the cases that CI runs.

## Example that triggers it

```csharp
var attempts = 0;
Verify(attempts++ == 0);
```

The build reports:

```text
warning VG0003: 'attempts++' changes state inside a Verify condition. Move it to a statement before the Verify call.
```

## The fix

Make the change in its own statement, then verify the result:

```csharp
var attempts = 0;
attempts++;
Verify(attempts == 1);
```

## When to suppress it

Suppress it when the change is the behaviour under test and a separate statement would hide that, such as `Verify((cached ??= Load()) is not null)` in a test of `??=` itself.
