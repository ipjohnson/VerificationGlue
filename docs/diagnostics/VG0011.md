# VG0011: VerifyEquivalent compares a type it cannot walk with Equals

## What it means

The generator writes a comparer for each `VerifyEquivalent` call that reads the public fields and properties of each type it reaches. A type it cannot walk compares with `Equals`. For most such types `Equals` is what you want, such as a string, an enum, a record or a type that implements `IEquatable<T>`. This warning names the types where it is not, at the `VerifyEquivalent` call, once for each type:

- A class or a struct with no public field or property, that does not implement `IEquatable<T>`, does not override `Equals` and is not a record. A class then compares by reference, so two instances with the same state differ. A struct compares with `ValueType.Equals`, and the message gives only its type name.
- A class or a struct with the same lack of an `Equals` of its own, which the generated code cannot name, such as a private class nested in a test class.
- An open generic type, such as `T` in a generic helper method that calls `VerifyEquivalent(actual, expected)`, or `List<T>`. The generator does not know the type, so it writes no comparer, and the call compares with `Equals` at run time.

The check covers the type passed to `VerifyEquivalent` and the type of each member, item and dictionary value that the comparer reaches. Types in a `System` or `Microsoft` namespace, interfaces and collections the comparer does not walk are left out.

A `CheckEquivalent` call gets the same warning, with `CheckEquivalent` in the message.

[`EquivalenceSpecs.cs`](../../test/VerificationGlue.Generator.Specs/EquivalenceSpecs.cs) holds the cases that CI runs.

## Example that triggers it

```csharp
public sealed class Token
{
    private readonly string _value;

    public Token(string value) => _value = value;
}

public sealed record Session(int Id, Token Token);

VerifyEquivalent(parsed, expected);
```

The build reports:

```text
warning VG0011: VerifyEquivalent compares 'Token' by reference, because it has no public field or property and does not implement IEquatable<Token>
```

## The fix

Give the comparer something to compare. Pick one:

- Make the state a public property, such as `public string Value { get; }`, so the comparer reads it.
- Implement `IEquatable<Token>`, or make `Token` a record, so `Equals` compares the state.
- Make a private nested type `internal`, so the generated code can name it.
- In a generic helper, call `VerifyEquivalent` with the concrete types at each call site, or move the call out of the helper.

## When to suppress it

Suppress it when comparing by reference is the check you mean, such as a member that must be the same instance on both sides. Suppress it in a generic helper whose types all compare well with `Equals`.
